# Yemen Water Survey — Metadata Contract

**Document Version:** 1.0.0  
**Status:** ACTIVE / SPECIFICATION  
**Scope:** Android Field Application & Data Exchange Protocol  
**Target Platform:** Yemen Water Survey System (Offline-First)

---

## 1. Executive Summary

This document defines the authoritative contract for all metadata fields attached to water facility survey records within the Yemen Water Survey application. It specifies:
- Fields persisted locally in the Room SQLite database (`SurveyRecordEntity`).
- Metadata exchanged during offline peer-to-peer sync (`.ywsync` packages).
- Exported fields in multi-sheet Excel reports (`.xlsx`) and PDF inspection certificates.
- Active system behaviors, validation gates, and items marked as **[PLANNED]** for future convergence with target requirements.

---

## 5. Facility-Specific Payload Serialization

Dynamic and hardcoded survey responses are serialized into dedicated JSON columns in `SurveyRecordEntity`:
1. `wellDetailsJson` (SurveyType = `WELL`):
   ```json
   {
     "wellNameAr": "بئر الأمل",
     "wellType": "BOREHOLE",
     "wellDepthM": 120.0,
     "pumpingMechanism": "SOLAR",
     "operationalStatus": "FUNCTIONAL"
   }
   ```
2. `springDetailsJson` (SurveyType = `SPRING`):
   ```json
   {
     "springNameAr": "عين وادي الغيل",
     "flowRateLps": 4.5,
     "waterClarity": "CLEAR",
     "dischargeSeasonality": "PERENNIAL"
   }
   ```
3. `damDetailsJson` (SurveyType = `DAM`):
   ```json
   {
     "damNameAr": "سد وادي مذاب",
     "structureType": "CONCRETE_DAM",
     "storageCapacityM3": 50000.0,
     "damHeightM": 12.5,
     "structuralCondition": "GOOD"
   }
   ```
4. `attachmentsJson`: Array of linked media references (Photo attachments with SHA-256 integrity hashes).

## 7. Target Contract Gap Summary & Planned Additions

| Target Requirement | Current Code Behavior | Status | Planned Alignment Action |
| :--- | :--- | :---: | :--- |
| `enumerator_code` matching `ENUM-\d{3,}` | Generates `ENUM-YEM-<6-HEX>` | ⚠️ FORMAT MISMATCH | Update regex generator to numeric scheme or accept alphanumeric standard. |
| Timezone in timestamps (ISO-8601 `XXX`) | Uses local `yyyy-MM-dd HH:mm:ss` | ⚠️ TIMEZONE MISSING | Standardize timestamp serialization to ISO-8601 `yyyy-MM-dd'T'HH:mm:ssXXX`. |
| Explicit `submitted_at` field | Uses `updatedAt` / `createdAt` | ⚠️ MISSING COLUMN | Add `submittedAt` timestamp populated when `workflowStatus = COMPLETED`. |
| GPS Accuracy Threshold `≤ 20m` | Enforces stricter `< 15m` | ✅ STRICTER (PASS) | Keep strict `< 15m` threshold as authoritative quality gate. |
| Dynamic XLSForm Reserved Names | Not checked on package import | ⚠️ VALIDATION GAP | Add reserved metadata keywords filter in `FormPackageValidator.kt`. |
